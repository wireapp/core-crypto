decryptMessage

open suspend override fun decryptMessage(conversationId: ConversationId, payload: ByteArray): List<DecryptionOutcome>(source)

Decrypts an MLS message received in the given conversation.

Commit races

A commit from another member supersedes any local pending commit and consumes the pending proposals it references. Our own commit, delivered back to us, is merged. Proposals and application messages leave local pending state untouched.

Decryption produces a list of outcomes

The first item in the returned list is always the outcome of decrypting the provided payload. This function will never return an empty list.

Sometimes a decrypted message is not yet processable, but is expected to be processable later given an appropriate trigger. For example, a commit may be delivered for decryption before a proposal it references. In that case, the message is buffered for automatic inclusion in a later decryption and the Deferred outcome variant is returned, indicating what this message is waiting for.

Sometimes a decrypted message is incorrect in some way which means it will never be processable. In that case, the Rejected outcome variant is returned, indicating what is wrong with the message. Rejected variants are not errors and will not cause transaction rollback.

If the decrypted message produces an event causing previously-buffered messages to be decrypted, i.e. an out-of-order proposal arriving after a commit which was deferred, the outcomes of those messages' decryption are appended to the output list in processing order.

If a commit ejects us from the group, no further messages are considered. This means that if we are ejected, the final message will always be a Commit variant with isActive: false.

Error handling

When decrypting buffered messages, we distinguish betwen infrastructural errors and other errors. Infrastructural errors are those which we would expect not to reappear if we re-attempted the decryption in a new, perfectly healthy environment.

If decryption of a buffered message triggers an infrastructural error, that error is propagated so that the transaction is rolled back. Once the environment is healthy, reattempting can be expected to succeed.

Non-infrastructural errors when decrypting buffered messages produce a log line, but they are not propagated, and the buffered message is dropped.

All errors produced when decrypting the initial message are propagated, whether or not they are infrastructural.
